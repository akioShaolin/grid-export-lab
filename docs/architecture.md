# Arquitetura e contratos

1. Túnel: Smartlogger/RS485 → master_client → TCP → slave_server → RS485/inversor. Porta 1502; enquadramento A5 5A, sequência de um byte, comprimento little-endian de dois bytes e payload RTU com CRC; keepalive binário e HELLO. Não é Modbus TCP padrão. HTTP de diagnóstico na porta 80. As duas pontas devem permanecer juntas.
2. Monitor: ESP mestre RTU lê o relé e fornece holding registers por Modbus TCP/502. v3 usa status/seq/idade em 0x3000–0x3002. v4 acrescenta frequência/cosseno e usa 0x0100–0x0102. v5 é experimento com snapshot 0x0200/32 e diagnóstico 0x0100/64, sem RTU habilitado. v6 retoma espelho com status 0x0100 e diagnóstico ampliado, configuração EEPROM, OTA e mDNS.
3. Gateway de inversor: ESP mestre RTU, TCP/8899 com linhas terminadas em newline. station aceita SET/SETPCT, PING, GET, HELLO; station2 acrescenta READPWR e resposta ACTPWR. Manter READY, OK, ERR e demais mensagens exatamente como nos fontes. Registros WEG preservados: 0x9D6B habilita limite, 0x9D6C define limite; station2 lê 0x9C8F.
4. Host: controle.py + station; controle2.py + station2. Ambos leem snapshot 0x0200/32 do lado do relé. O v5 encontrado tem o formato esperado, mas RTU desligado e snapshot de teste. Não trocar por v6 sem adaptar protocolo; essa adaptação não foi feita. O autor confirmou o fluxo: o computador lia os dados presentes no logger conectado ao URP6000, calculava o controle e enviava os comandos ao logger conectado aos inversores. A ressalva documental se limita à versão exata do firmware do logger URP6000 usada com cada script; não há dúvida sobre a origem física das medidas.
5. Edge: ESP lê espelho URP por Modbus TCP/502 (0x0100, 0x003C, 0x02CD), calcula PI e comanda inversores RTU. Referência de medição explicitada no fonte: v6. API HTTP do ESP: /api/status e /api/stats; coletor Python serve /api/state, /api/history e /api/latest na porta 8000. Headers PROGMEM pertencem ao firmware da mesma pasta; HTML histórico pertence ao coletor da mesma versão.

Não há migração automática entre mapas. A biblioteca integrada mantém seu comportamento bloqueante histórico. Os nomes que identificavam a instalação foram alterados em firmware, coletor, HTML e batch correspondentes; rotas e chaves JSON foram mantidas. O número mágico EEPROM e a estrutura persistida também foram preservados. Valores já gravados na EEPROM precisam de revisão local antes de testes.
